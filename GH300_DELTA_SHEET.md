## 1. CLI Commands & Shell Integration (Топ ловушек CertSafari)

В вопросах по Copilot в терминале экзамен проверяет разницу между **двумя инструментами**:

1. **GitHub CLI Copilot Extension** (`gh copilot ...`) — расширение официального CLI `gh`.
2. **Standalone Copilot CLI** (`copilot ...`) — новый агентный интерактивный инструмент.

### А. Расширение `gh copilot` (Extension)

* **Установка расширения**:

  ```bash
  gh extension install github/gh-copilot
  ```

* **Обновление**:

  ```bash
  gh extension upgrade gh-copilot
  ```

* **Две ключевые субкоманды**:
  * `gh copilot suggest [prompt]` — предложить команду по описанию на естественном языке.
  * `gh copilot explain [command]` — объяснить готовую команду.
* **Настройка алиасов оболочки (САМЫЙ ЧАСТЫЙ ВОПРОС НА ЭКЗАМЕНЕ)**:
  Чтобы вызывать Copilot быстро через алиасы `ghcs` (Copilot Suggest) и `ghce` (Copilot Explain), используется команда:

  ```bash
  gh copilot alias -- <shell-name>
  ```

  Примеры добавления в профиль оболочки:
  * **Zsh** (`~/.zshrc`):

    ```bash
    echo 'eval "$(gh copilot alias -- zsh)"' >> ~/.zshrc
    ```

  * **Bash** (`~/.bashrc`):

    ```bash
    echo 'eval "$(gh copilot alias -- bash)"' >> ~/.bashrc
    ```

  * **PowerShell** (`$PROFILE`):

    ```powershell
    $(&gh copilot alias -- powershell) | Out-String | Invoke-Expression
    ```

  > ⚠️ **Экзаменационная ловушка**: Команды `gh copilot config --shell ...` **НЕ СУЩЕСТВУЕТ**. Всегда используется субкоманда `alias` с разделителем `--` и именем шелла (`bash`, `zsh`, `powershell`).
* **Алиасы по умолчанию, которые генерируются этой командой**:
  * `ghcs` = `gh copilot suggest`
  * `ghce` = `gh copilot explain`
* **Флаги целевого выполнения для `gh copilot suggest`**:
  * `-t shell` (по умолчанию) — общие команды оболочки bash/zsh/sh.
  * `-t gh` — команды GitHub CLI (`gh repo clone` и т.д.).
  * `-t git` — чистые команды Git (`git cherry-pick` и т.д.).
* **Телеметрия в CLI**:
  * Отключение сбора данных: `gh copilot config` -> выбор опции отключения передачи телеметрии.

### Б. Standalone GitHub Copilot CLI (`copilot`)

* **Запуск интерактивной сессии**:

  ```bash
  copilot
  ```

* **Одноразовый (one-shot) промпт**:

  ```bash
  copilot -i "explain brew install git"
  copilot -i "suggest find large files and delete them"
  ```

* **Слэш-команды внутри сессии (Session Control)**:
  * `/help` — список команд.
  * `/explain <command>` — разбор команды.
  * `/suggest <task>` — предложение команды.
  * `/revise` — правка предыдущего предложения.
  * `/model <model>` — выбор модели для сессии.
  * `/theme [auto|dark|light]` — настройка темы терминала.
  * `/list-dirs` — список доверенных/разрешенных директорий.
  * `/reset-allowed-tools` — сброс разрешенных инструментов.
  * `/exit` — выход из интерактивного режима.
* **Песочницы (Sandboxing) в CLI**:
  * **Local Sandbox**: запускается командой `/sandbox enable` прямо внутри интерактивной сессии. Изолирует запуск команд и операции с файлами на локальной машине.
  * **Cloud Sandbox**: запускается флагом `copilot --cloud`. Выполняется в инфраструктуре Azure Container Apps в облаке GitHub. Поддерживает состояния: `Active`, `Stopped`, `Deleted`.

## 3. GitHub MCP Server (Model Context Protocol)

Модуль 12 проверяет точную архитектуру и подключение официального GitHub MCP Server:

* **Что такое MCP**: Открытый протокол (от Anthropic), стандартизирующий подключение LLM к внешним инструментам и источникам данных («USB-C для AI»).
* **Hosted GitHub MCP Server**:
  * GitHub предоставляет официальный **облачный hosted MCP-сервер**, исключающий необходимость запускать Docker или локальные сервисы.
  * **Официальный Server URL**: `https://api.githubcopilot.com/mcp/`
  * **Тип транспорта (Transport Type)**: `HTTP (HTTP or Server-Sent Events / SSE)`.
* **Аутентификация**:
  * Быстрая: OAuth-логин в 1 клик через веб-браузер.
  * Расширенная (Advanced): **Personal Access Token (PAT)** с соответствующими скоупами (read/write issues, pull requests, repo).
* **Как активировать в VS Code**:
  1. Открыть панель Copilot Chat.
  2. Переключиться в **Agent Mode**.
  3. В меню **Select Tools** выбрать доступные инструменты GitHub MCP Server.
* **Поддержка в Copilot Cloud Agent**:
  * Cloud Agent поддерживает **только MCP Tools** (не поддерживает MCP Resources и MCP Prompts).
  * Remote MCP-серверы, требующие интерактивной OAuth-авторизации, в Cloud Agent **не поддерживаются** (конфигурируются админами через JSON в репозитории).

## 4. Copilot Cloud Agent vs Agent Mode в IDE

* **Copilot Agent Mode (в IDE / VS Code)**:
  * Интерактивный локальный агент. Запускается прямо в панели чата редактора.
  * Может автономно создавать файлы, править код, запускать терминальные команды и тесты, ожидая локального подтверждения действий разработчиком.
* **Copilot Cloud Agent (на GitHub.com)**:
  * **Где выполняется**: Запускается в облачной изолированной среде **GitHub Actions** (Azure Container Apps).
  * **Сетевая безопасность**: По умолчанию имеет **ограниченный фаервол (Internet restricted by default)**. Внешние URL блокируются, если не разрешены явными правилами.
  * **Как назначить задачу**:
    * Назначить `@copilot` исполнителем (Assignee) в GitHub Issue.
    * Запустить через Copilot Chat на GitHub.com.
    * Через GitHub Mobile или REST API / CLI.
  * **Жизненный цикл работы Cloud Agent**:
    1. Создает изолированную ветку в репозитории (например, `copilot/fix-login-error`).
    2. Анализирует проект, выполняет изменения и коммитит их.
    3. Открывает **Draft Pull Request (черновик PR)**.
    4. Пользователь проверяет PR, может давать фидбек через комментарии `@copilot` прямо в PR.
    5. **Агент никогда не сливает PR самостоятельно** — финальный merge всегда за человеком.

## 5. Pull Requests & Code Review с Copilot

Экзамен часто проверяет полномочия Copilot в процессах ревью:

* **Роль Copilot в PR Review**:
  * На GitHub.com Copilot можно добавить как ревьюера через выпадающий список **Reviewers**.
  * Copilot оставляет **ТОЛЬКО комментарии (Comment Review)**.
  * ⚠️ **Экзаменационная ловушка**: Copilot **НЕ МОЖЕТ** нажать «Approve» или «Request Changes». Он никогда не блокирует merge и не удовлетворяет обязательные требования Branch Protection rules по аппрувам от людей.
* **Генерация PR Summary**:
  * Генерирует 1–2 абзаца описания изменений и маркированный список (bullet points) по diff ветки.
  * Расходует **1–2 PRU (Premium Request Units)**.
* **Конфигурация правил ревью**:
  * Использует файл `.github/copilot-instructions.md`.
  * Если в файле написано: *«Всегда требовать типы параметров и запрещать `any` в TypeScript»*, Copilot сгенерирует inline-замечание в строке diff, если встретит нарушение.

## 6. Microsoft & GitHub 6 Принципов Responsible AI

Вендорные экзамены Microsoft любят сценарии на выбор принципа:

| Принцип | Суть концепции | Типичный экзаменационный сценарий |
| :--- | :--- | :--- |
| **Fairness (Справедливость)** | AI должен относиться ко всем группам людей одинаково, без предвзятости | Проверка моделей на отсутствие демографического/гендерного дисбаланса, аудит тренировочных выборок. |
| **Reliability & Safety (Надежность и безопасность)** | Системы должны работать стабильно, противостоять вредоносным атакам и ошибкам | Тестирование граничных условий, защита от jailbreak/инъекций промптов, валидация сгенерированного кода перед деплоем. |
| **Privacy & Security (Конфиденциальность)** | Защита пользовательских данных и интеллектуальной собственности | Удаление PII (персональных данных), шифрование в HSM, ненакопление пользовательского кода для дообучения. |
| **Inclusiveness (Инклюзивность)** | Доступность для всех людей, включая людей с ограниченными возможностями | Добавление поддержки доступности (a11y), скринридеров, мультиязычной локализации. |
| **Transparency (Прозрачность)** | Понятность работы системы и информирование пользователя | Четкое уведомление о том, что код сгенерирован AI; объяснение того, как модель собирает контекст. |
| **Accountability (Подотчетность)** | **Люди несут окончательную ответственность** за результат работы AI | Человек обязан проверять и утверждать PR; разработчик, а не Copilot, отвечает за безопасность коммита. |

## 7. Content Exclusions (Правила и Ограничения)

* **Где настраиваются**: В настройках Организации или Предприятия: `Settings -> Copilot -> Content exclusion`.
* **Что делают**: Блокируют Copilot от чтения файлов, директорий и целых репозиториев. Если файл открыт в IDE, автодополнение отключается, а контекст файла **не отправляется** в LLM.
* **Визуальный индикатор в IDE**: Иконка GitHub Copilot в строке состояния (Status Bar) перечеркивается **диагональной линией** (`/`). При наведении всплывает тултип, сообщающий, кем заблокирован файл (Parent repo или Org).
* **Срок применения (Propagation Time)**:
  * После настройки в UI изменения применяются в активных IDE в течение **до 30 минут**.
  * Чтобы применить немедленно: перезагрузить окно редактора (Reload Window) или обновить статус в расширении.
* **Синтаксис путей**:
  * Исключить репозиторий целиком: `https://github.com/org-name/repo-name`
  * Исключить пути по паттерну: `**/.env`, `src/secrets/**`, `*.key`
* ⚠️ **Экзаменационная ловушка**: `.gitignore` **НЕ ЯВЛЯЕТСЯ** Content Exclusion! Если файл в `.gitignore`, но открыт в соседней вкладке VS Code, Copilot прочитает его содержимое через Jaccard Similarity, если файл не добавлен в *Content Exclusions*.

## 8. Public Code Matching & Legal Protections

* **Что такое Public Code Filter**:
  * Фильтр совпадений с публичным кодом. Блокирует предложения длиной **~150 символов** (около 15-20 строк кода), если они дословно совпадают с существующим публичным кодом на GitHub.
* **Настройки политики (Policy settings)**:
  * `Allowed` (Разрешено выдавать с указанием источника)
  * `Blocked` (Запрещено: если найден матч > 150 символов, предложение отбрасывается)
  * `No policy` (наследовать вышестоящую политику)
* **Защита от претензий по интеллектуальной собственности (IP Indemnification / Copyright Defense Commitment)**:
  * Предоставляется корпоративным клиентам при условии, что в политиках включен фильтр **Blocked matching public code**.

## 9. Хоткеи, Контекст и Промптинг

### А. Хоткеи по умолчанию (VS Code)

| Действие | Windows / Linux | macOS |
| :--- | :--- | :--- |
| Принять всё дополнение | `Tab` | `Tab` |
| Принять одно слово (Partial accept) | `Ctrl + ->` (Right Arrow) | `Cmd + ->` (Right Arrow) |
| Отклонить дополнение | `Esc` | `Esc` |
| Следующее предложение (Cycle next) | `Alt + ]` | `Option (⌥) + ]` |
| Предыдущее предложение (Cycle prev) | `Alt + [` | `Option (⌥) + [` |
| Открыть панель предложений (Suggestions Pane, до 10 вариантов) | `Ctrl + Enter` | `Cmd + Enter` |
| Открыть встроенный чат (Inline Chat) | `Ctrl + I` | `Cmd + I` |

### Б. Copilot Chat: Участники (`@`), Слэш-команды (`/`) и Контекст (`#`)

* **Чат-агенты / Участники (`@`)**:
  * `@workspace` — строит индекс символов, сканирует весь открытый проект.
  * `@terminal` — объясняет вывод последней команды или ошибки терминала.
  * `@vscode` — отвечает на вопросы по настройкам самого редактора VS Code.
  * `@github` — подключение к веб-контексту GitHub (Issues, PRs, Discussions).
* **Слэш-команды (`/`) в IDE**:
  * `/doc` — генерирует комментарии/docstrings для выделенного кода.
  * `/explain` — объясняет выделенный код.
  * `/fix` — предлагает исправление бага в выделенном блоке.
  * `/tests` — генерирует unit-тесты.
  * `/new` — скаффолдинг новой структуры проекта.
* **Переменные контекста (`#`)**:
  * `#file:path` — явная передача конкретного файла.
  * `#selection` — текущий выделенный фрагмент кода.
  * `#editor` — видимая часть активного редактора.
  * `#terminalLastCommand` — вывод последней команды терминала.

### В. Механизм контекста (Prompt Processing Flow)

1. **Jaccard Similarity & Neighboring Tabs**: Copilot ранжирует открытые вкладки редактора. Вкладки на том же языке программирования с похожей лексикой включаются в промпт с наивысшим приоритетом.
2. **Fill-In-The-Middle (FIM)**: Модели отправляется код до курсора (Prefix) и после курсора (Suffix).
3. **Repository Instructions**: Автоматически подмешивается `.github/copilot-instructions.md`.

## 10. Copilot Spaces (Web-контекст)

* **Copilot Spaces** (`github.com/copilot/spaces`):
  * Доступно в **Enterprise**.
  * Индивидуальные или принадлежащие организации базы знаний под конкретный сервис/проект.
  * **Главное правило экзамена**: Привязанные файлы репозитория в Spaces всегда читаются из **ветки по умолчанию (default branch, main)**. Не из рабочих веток!
  * Права доступа: Строго наследуются из GitHub (пользователь не увидит в Space то, к чему у него нет доступа в репозитории).

## 11. Premium Request Units (PRU)

* **Что такое PRU**: Единицы измерения вычислительных затрат для сложных / мультиагентных запросов.
* **Расход PRU**:
  * Генерация PR summary: 1–2 PRU.
  * Автоматический Code Review в PR: 1 PRU за прогон.
  * Agent Mode / Cloud Agent: ~1 PRU за каждый шаг передачи (handoff), 2–3 PRU за стандартный цикл.
  * Reasoning-модели: до 4+ PRU.
* **Что НЕ расходует PRU**: Стандартный inline autocompletion (ghost text) в IDE.
