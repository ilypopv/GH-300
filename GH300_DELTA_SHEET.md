> **Цель этого документа**: Полная фильтрация «воды». Здесь собраны **только** жесткие факты, синтаксис команд, границы планов, неинтуитивные правила и ловушки сертификационного экзамена **GH-300 (GitHub Copilot)**.

## 1. CLI Commands & Shell Integration (Топ ловушек CertSafari)

В вопросах по Copilot в терминале экзамен проверяет разницу между **двумя инструментами**:

1. **GitHub CLI Copilot Extension** (`gh copilot ...`) — расширение официального CLI `gh`.
2. **Standalone Copilot CLI** (`copilot ...`) — новый агентный интерактивный инструмент.

### А. Расширение `gh copilot` (Extension)

* **Установка расширения**:

  ```bash
  gh extension install github/gh-copilot
  ```

* **Обновление**:

  ```bash
  gh extension upgrade gh-copilot
  ```

* **Две ключевые субкоманды**:
  * `gh copilot suggest [prompt]` — предложить команду по описанию на естественном языке.
  * `gh copilot explain [command]` — объяснить готовую команду.
* **Настройка алиасов оболочки (САМЫЙ ЧАСТЫЙ ВОПРОС НА ЭКЗАМЕНЕ)**:
  Чтобы вызывать Copilot быстро через алиасы `ghcs` (Copilot Suggest) и `ghce` (Copilot Explain), используется команда:

  ```bash
  gh copilot alias -- <shell-name>
  ```

  Примеры добавления в профиль оболочки:
  * **Zsh** (`~/.zshrc`):

    ```bash
    echo 'eval "$(gh copilot alias -- zsh)"' >> ~/.zshrc
    ```

  * **Bash** (`~/.bashrc`):

    ```bash
    echo 'eval "$(gh copilot alias -- bash)"' >> ~/.bashrc
    ```

  * **PowerShell** (`$PROFILE`):

    ```powershell
    $(&gh copilot alias -- powershell) | Out-String | Invoke-Expression
    ```

  > ⚠️ **Экзаменационная ловушка**: Команды `gh copilot config --shell ...` **НЕ СУЩЕСТВУЕТ**. Всегда используется субкоманда `alias` с разделителем `--` и именем шелла (`bash`, `zsh`, `powershell`).
* **Алиасы по умолчанию, которые генерируются этой командой**:
  * `ghcs` = `gh copilot suggest`
  * `ghce` = `gh copilot explain`
* **Флаги целевого выполнения для `gh copilot suggest`**:
  * `-t shell` (по умолчанию) — общие команды оболочки bash/zsh/sh.
  * `-t gh` — команды GitHub CLI (`gh repo clone` и т.д.).
  * `-t git` — чистые команды Git (`git cherry-pick` и т.д.).
* **Телеметрия в CLI**:
  * Отключение сбора данных: `gh copilot config` -> выбор опции отключения передачи телеметрии.

---

### Б. Standalone GitHub Copilot CLI (`copilot`)

* **Запуск интерактивной сессии**:

  ```bash
  copilot
  ```

* **Одноразовый (one-shot) промпт**:

  ```bash
  copilot -i "explain brew install git"
  copilot -i "suggest find large files and delete them"
  ```

* **Слэш-команды внутри сессии (Session Control)**:
  * `/help` — список команд.
  * `/explain <command>` — разбор команды.
  * `/suggest <task>` — предложение команды.
  * `/revise` — правка предыдущего предложения.
  * `/model <model>` — выбор модели для сессии.
  * `/theme [auto|dark|light]` — настройка темы терминала.
  * `/list-dirs` — список доверенных/разрешенных директорий.
  * `/reset-allowed-tools` — сброс разрешенных инструментов.
  * `/exit` — выход из интерактивного режима.
* **Песочницы (Sandboxing) в CLI**:
  * **Local Sandbox**: запускается командой `/sandbox enable` прямо внутри интерактивной сессии. Изолирует запуск команд и операции с файлами на локальной машине.
  * **Cloud Sandbox**: запускается флагом `copilot --cloud`. Выполняется в инфраструктуре Azure Container Apps в облаке GitHub. Поддерживает состояния: `Active`, `Stopped`, `Deleted`.

## 3. Content Exclusions (Правила и Ограничения)

* **Где настраиваются**: В настройках Организации или Предприятия: `Settings -> Copilot -> Content exclusion`.
* **Что делают**: Блокируют Copilot от чтения файлов, директорий и целых репозиториев. Если файл открыт в IDE, автодополнение отключается, а контекст файла **не отправляется** в LLM.
* **Визуальный индикатор в IDE**: Иконка GitHub Copilot в строке состояния (Status Bar) перечеркивается **диагональной линией** (`/`). При наведении всплывает тултип, сообщающий, кем заблокирован файл (Parent repo или Org).
* **Срок применения (Propagation Time)**:
  * После настройки в UI изменения применяются в активных IDE в течение **до 30 минут**.
  * Чтобы применить немедленно: перезагрузить окно редактора (Reload Window) или обновить статус в расширении.
* **Синтаксис путей**:
  * Исключить репозиторий целиком: `https://github.com/org-name/repo-name`
  * Исключить пути по паттерну: `**/.env`, `src/secrets/**`, `*.key`
* **Ограничение экзамена**: Content Exclusions действуют только на членов организации с управляемыми лицензиями. Если разработчик коммитит в репозиторий через личный аккаунт вне org-контекста, exclusion может не подтянуться.

## 4. Public Code Matching & Legal Protections

* **Что такое Public Code Filter**:
  * Фильтр совпадений с публичным кодом. Блокирует предложения длиной **~150 символов** (около 15-20 строк кода), если они дословно совпадают с существующим публичным кодом на GitHub.
* **Настройки политики (Policy settings)**:
  * `Allowed` (Разрешено выдавать с указанием источника)
  * `Blocked` (Запрещено: если найден матч > 150 символов, предложение отбрасывается)
  * `No policy` (наследовать вышестоящую)
* **Защита от претензий по интеллектуальной собственности (IP Indemnification)**:
  * Microsoft / GitHub предоставляют юридическую защиту (Copyright Defense Commitment) корпоративным клиентам при условии, что в политиках включен фильтр **Blocked matching public code**.

## 5. Контекст, Промптинг и IDE Hotkeys

### А. Хоткеи по умолчанию (VS Code)

| Действие | Windows / Linux | macOS |
| :--- | :--- | :--- |
| Принять всё дополнение | `Tab` | `Tab` |
| Принять одно слово (Partial accept) | `Ctrl + ->` (Right Arrow) | `Cmd + ->` (Right Arrow) |
| Отклонить дополнение | `Esc` | `Esc` |
| Следующее предложение (Cycle next) | `Alt + ]` | `Option (⌥) + ]` |
| Предыдущее предложение (Cycle prev) | `Alt + [` | `Option (⌥) + [` |
| Открыть панель предложений (Suggestions Pane, до 10 вариантов) | `Ctrl + Enter` | `Cmd + Enter` |
| Открыть встроенный чат (Inline Chat) | `Ctrl + I` | `Cmd + I` |

### Б. Copilot Chat: Участники (`@`) и Слэш-команды (`/`)

* **Чат-агенты / Участники (`@`)**:
  * `@workspace` — сканирует весь открытый проект, строит индекс символов, находит релевантные файлы.
  * `@terminal` — объясняет вывод последней команды или ошибки в интегрированном терминале.
  * `@vscode` — знает всё о настройках самого редактора VS Code, клавиатурных сочетаниях и UI.
  * `@github` — подключение к веб-контексту GitHub (Issues, PRs, Discussions).
* **Слэш-команды (`/`) в IDE**:
  * `/doc` — генерирует документацию и docstrings для выделенного блока кода.
  * `/explain` — объясняет выделенный код.
  * `/fix` — находит проблему/баг в выделенном коде и предлагает исправление.
  * `/tests` — генерирует unit-тесты для выделенного метода/класса.
  * `/new` — создает скаффолдинг нового проекта или структуры файлов с нуля.
  * `/clear` — очищает текущую сессию чата.
* **Переменные контекста (`#`)**:
  * `#file:имя_файла` — явное добавление файла в контекст запроса.
  * `#selection` — текущее выделение кода.
  * `#editor` — видимая область активного редактора.
  * `#terminalLastCommand` — вывод последней команды в терминале.

### В. Механизм сбора контекста (Prompt Processing Flow)

1. **Jaccard Similarity & Neighboring Tabs**: Copilot анализирует открытые вкладки редактора. Вкладки на том же языке программирования с похожей лексикой включаются в промпт с наивысшим приоритетом.
2. **Path Context**: Путь к текущему файлу передается в LLM, чтобы модель понимала архитектурный слой (например, `src/controllers/userController.js`).
3. **Cursor Position**: Код до курсора (Prefix) и код после курсора (Suffix) передаются в модель (Fill-In-The-Middle, FIM).

## 6. Custom Instructions & Репозиторные правила

* **Файл инструкций**: `.github/copilot-instructions.md` в корне репозитория (или в ветке по умолчанию).
* **Для чего используется**:
  * Автоматически подмешивается в системный промпт Copilot Chat в IDE.
  * Используется Copilot при Code Review пулл-реквестов на GitHub.com.
  * Используется Copilot Cloud Agent.
* **Что туда помещают**: Стандарты кодирования команды, соглашения об именовании, используемые библиотеки утверждений для тестов, запрещенные пакеты.

## 7. Copilot Spaces & Copilot on GitHub.com

* **Copilot Spaces** (`github.com/copilot/spaces`):
  * Доступно в **Enterprise**.
  * Позволяет создать изолированное контекстное пространство для конкретной темы/сервиса.
  * Источники (Attachments): привязанные репозитории, файлы, Issues, PRs и кастомные текстовые инструкции.
  * **Правило экзамена**: Привязанные файлы в Spaces всегда читаются из **ветки по умолчанию (default branch, main)**. Не из фича-веток!
  * Разрешения: наследуются от стандартной ролевой модели GitHub (пользователь не может получить через Space доступ к репозиторию, к которому у него нет прав на GitHub).

## 8. Premium Request Units (PRU)

* **Что такое PRU**: Единицы измерения вычислительных затрат для сложных / мультиагентных запросов Copilot.
* **Где расходуются PRU**:
  * Генерация summary пулл-реквеста на GitHub.com (1–2 PRU).
  * Автоматический Copilot Code Review на GitHub.com (1 PRU за публикацию отзыва).
  * Запуск Agent Mode / Cloud Agent (обычно ~1 PRU на каждый шаг передачи/handoff, 2–3 PRU на стандартный цикл драфт-ревью).
  * Продвинутые reasoning-модели при глубоком анализе (до 4+ PRU за запрос).
* **Что НЕ расходует PRU**: Стандартный inline autocompletion (ghost text) в IDE.

## 9. Вопросы-ловушки с разбором формулировок

### Кейс 1: CLI Shell Config

* ❌ **Ловушка**: `gh copilot config --shell zsh` или `gh copilot setup -s zsh`
* ✅ **Правильно**: `gh copilot alias -- zsh` (и обернуть в `eval "$(gh copilot alias -- zsh)"`).
* **Почему**: `gh copilot` — это Go-бинарник расширения CLI. Он не может напрямую модифицировать память запущенного родительского шелла. Чтобы создать алиасы `ghcs` и `ghce`, он должен напечатать на stdout shell-скрипт с функциями, который родительский шелл выполняет через `eval`.

### Кейс 2: Просмотр вариантов дополнений

* ❌ **Ловушка**: Нажать `F1` или `Tab` дважды.
* ✅ **Правильно**: `Alt+]` (след.), `Alt+[` (пред.) или `Ctrl+Enter` (открыть отдельную вкладку с 10 вариантами).

### Кейс 3: Защита секретов и файлов

* ❌ **Ловушка**: Добавить файл в `.gitignore`.
* ✅ **Правильно**: Настроить **Content Exclusions** в настройках репозитория/организации на GitHub.
* **Почему**: `.gitignore` влияет только на `git status` и коммиты. Copilot всё равно читает файлы, игнорируемые гитом, если они открыты в соседних вкладках, если на них нет явного Content Exclusion!
