## 1. A junior developer on a Windows workstation wants to configure the `gh copilot` CLI extension so that running `ghcs` in PowerShell launches `gh copilot suggest`. They run `gh copilot alias powershell` but nothing is registered. What is the correct approach?

`GitHub Copilot Plans and Features`

- [ ] Run `gh copilot config --shell powershell` and restart the terminal.
- [ ] Run `gh copilot alias powershell` and add the output to `$PROFILE` manually.
- [x] Add `$(&gh copilot alias -- powershell) | Out-String | Invoke-Expression` to `$PROFILE` and reload it.
- [ ] Run `gh extension install github/gh-copilot --shell powershell`.

<details>
<summary>Explanation</summary>

**Correct**

- **`$(&gh copilot alias -- powershell) | Out-String | Invoke-Expression`** — `gh copilot alias -- <shell>` prints shell-specific function definitions to stdout. In PowerShell the output must be captured and piped through `Out-String | Invoke-Expression` to evaluate the function definitions in the current session. Adding this line to `$PROFILE` makes it permanent. The double-dash `--` separator is required to prevent the shell name from being interpreted as a flag.

**Why the others are wrong**

- **`gh copilot config --shell powershell`** — This flag does not exist in the `gh copilot` CLI extension. There is no `config --shell` subcommand.
- **`gh copilot alias powershell` added to `$PROFILE` manually** — Without the `--` separator the argument is malformed; additionally the raw output of the command cannot be stored as a variable without the `$()` capture syntax.
- **`gh extension install ... --shell powershell`** — The `install` subcommand does not accept a `--shell` flag. Shell integration is configured after installation via the `alias` subcommand.

**References**

- <https://docs.github.com/en/copilot/managing-copilot/configure-personal-settings/installing-the-github-copilot-extension-in-your-environment>

</details>

`GitHub Copilot Plans and Features`

- [ ] `copilot -i "explain git log --oneline -10"`
- [ ] `ghcs -t git "explain git log --oneline -10"`

<details>
<summary>Explanation</summary>

**Correct**

- **`gh copilot explain "git log --oneline -10"`** — `gh copilot explain` (aliased as `ghce`) is specifically designed to receive a command string and return a natural-language explanation of what that command does. Passing the full command as the argument produces an explanation of every flag.

**Why the others are wrong**

- **`gh copilot suggest "explain git log ..."`** — `suggest` generates a new shell command from a task description; it is the wrong subcommand for explaining an existing command.
- **`copilot -i "explain git log ..."`** — This is valid for the standalone `copilot` CLI but is a different tool from the `gh copilot` extension. The question asks about `gh copilot`.
- **`ghcs -t git "explain ..."`** — `ghcs` (suggest) with `-t git` is for generating Git commands, not explaining them.

<summary>Explanation</summary>

**Correct**
